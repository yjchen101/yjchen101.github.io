## 内存对齐（Memory Alignment）

就是如何计算一个结构体的大小？

一个大前提，CPU 每次读的时候，都只能整数倍的读。

从大到小排可以减少结构体的 padding。

> 算 struct 和 union（本质上是不同的操作内存的方式）。

使用 union 按照里面最大的大小来算，里面定义了对于 bit 不同的解释方式，可以是 int，可以是 char，可以是 double，目的是提高灵活性，节省内存。

### 两条规则

- **起始偏移规则：** 每个成员变量相对于结构体起始地址的偏移量（Offset），必须是该成员类型大小（或对齐模数）的**整数倍**。
- **结构体总大小规则：** 结构体的总大小必须是其内部**最大基本类型成员**大小的**整数倍**。
- **空隙填充（Padding）：** 如果不满足上述条件，编译器会在成员之间或末尾自动填充一些"无意义"的字节。

### 规则 0：结构体起始地址的"对齐约束"

编译器和操作系统内存管理器（Allocators）共同保证：**一个结构体变量在内存中的起始地址，必须是该结构体中"最大基本类型成员大小"的整数倍。**

**结构体的起始地址，必须是其内部"最大对齐模数"（通常是占用空间最大的基本类型成员）的整数倍。** 这样就可以保证都是对齐的。

### 为什么两条规则合起来就够

我们可以把整个对齐逻辑简化为一个数学等式：

成员绝对地址 = 结构体起始地址 (Base) + 成员偏移量 (Offset)

- **规则 1 (Offset)**：保证了 **Offset** 是对齐的。
- **规则 0 (Base)**：保证了 **Base** 是对齐的。
- **数学原理**：两个 N 的倍数相加，其结果必然还是 N 的倍数。

如何调整结构体的顺序让它 padding 最小呢？

从大到小排即可

## 环形缓冲区

FIFO：

- 内存固定
- 在生产者消费者这类中非常合适

结构：

- 数组（留一个空闲做判断）
- 读写指针
- `ridx == widx` 空
- `widx + 1 == ridx` 满

## 柔性数组

- 变长数组
- 和普通的变长指针，就是在 malloc 的时候自己指定多少，而不是在动态在内存中改变
- 必须要是结构体里面的最后一位
